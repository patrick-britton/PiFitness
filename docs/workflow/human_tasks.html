TASK 5.22 Pi Recovery Drill

[human] Replaces old 5.5d. Schedule a maintenance window. First run a normal test-up and test-down with --keep-db; verify PRD is restored before continuing. Then use only the explicit failpoints from 5.21 to interrupt test-up at selected transitions after the durable state checkpoint. For each drill, run test-down and verify PRD FastAPI, PM2 frontend, timers/services, HTTPS health, production commit, and exact baseline data checks. Do not use an arbitrary Ctrl+C point that occurs before state is written. Retain the dump and TEST DB until the recovery evidence is reviewed. Record the failpoint, command output, PRD process states, DB identity/marker, and before/after exact row counts in PROGRESS.md.
