Human Tasks 5.5d and 5.6 - Full Explicit Guide

Scope: This guide covers pushing the phase branch, fetching it to the Pi, running test-up/test-down, applying migrations, phone testing, and full rollback. It addresses production downtime and recovery.

0. Downtime and rollback summary

Downtime: YES. test-up stops PRD services and timers for the duration of testing. Plan a maintenance window.

Rollback principle: PRD data is never written during testing. test-down restarts PRD from its untouched checkout. If test-down fails, use the rollback commands in Section 8.

TEST DB: test-up creates pifitness_test from the stopped PRD DB. If it already exists, test-up drops/recreates it. Ensure the dev role can create databases.

1. Push and fetch the phase branch (DEV to Pi)

Description: Push the agent branch from DEV, then fetch it on the Pi.

On DEV: git push origin agent/phase-3

Expected: branch pushed; no errors.

On Pi: cd ~/PiFitness git fetch origin git branch -a | grep agent/phase-3

Expected: branch listed as origin/agent/phase-3.

2. Baseline (before testing)

Description: Record PRD commit and row counts.

cd ~/PiFitness git rev-parse HEAD git status --short
psql -U dev -d pifitness -c "SELECT schemaname,tablename,n_live_tup FROM pg_stat_user_tables ORDER BY tablename;" > /tmp/prd_counts_before.txt cat /tmp/prd_counts_before.txt

Expected: row counts saved; no git changes.

3. Test-up (creates test DB and test checkout)

Description: Run test-up against the phase branch. This stops PRD services, so downtime begins.

~/PiFitness/deploy/scripts/test-up.sh agent/phase-3

Expected: prints 8 steps and test-up complete.; creates ~/.pifitness-test-state and ~/PiFitness-test.

cat ~/.pifitness-test-state systemctl --user status pifitness-fastapi-test.service pm2 status

Expected: state file shows PRD_COMMIT, DUMP_PATH, REF; test service active; pm2 shows pifitness-next-test.

4. Venv and migrations (Task 5.6)

Description: Create test venv, editable install, apply and time migrations.

cd ~/PiFitness-test/backend python3 -m venv .venv .venv/bin/pip install -e . .venv/bin/python -c "import pifitness; print(pifitness.__file__)"

Expected: editable install resolves pifitness to ~/PiFitness-test/backend/pifitness.

cd ~/PiFitness-test time for f in deploy/migrations/*.sql; do echo "applying $f"; psql -U dev -d pifitness_test -v ON_ERROR_STOP=1 -f "$f"; done

Expected: all migration SQL files apply without error; record elapsed time.

5. Phone testing (Task 5.6)

Description: Start test units and walk features over HTTPS on phone.

systemctl --user start pifitness-fastapi-test.service pm2 start ~/PiFitness-test/deploy/scripts/ecosystem.config.js curl -k https://localhost/api/health

Expected: health returns 200; frontend reachable via HTTPS hostname.

Walk: login, activities, health dashboard, food, music, settings. Record failures as backlog IDs; do not fix now.

6. Test-down (restore PRD)

Description: Stop test units, drop test DB (marker must be test), restart PRD.

~/PiFitness/deploy/scripts/test-down.sh

Expected: test-down complete.; state file removed; PRD service active.

systemctl --user status pifitness-fastapi.service curl -k https://localhost/api/health psql -U dev -d pifitness -c "SELECT schemaname,tablename,n_live_tup FROM pg_stat_user_tables ORDER BY tablename;" > /tmp/prd_counts_after.txt diff /tmp/prd_counts_before.txt /tmp/prd_counts_after.txt && echo "ROW COUNTS MATCH"

7. Failure injection drill (Task 5.5d)

Description: Run test-up, interrupt mid-run, then recover with test-down.

~/PiFitness/deploy/scripts/test-up.sh agent/phase-3 # Press Ctrl+C during Step 6 (checkout) or later
~/PiFitness/deploy/scripts/test-down.sh systemctl --user status pifitness-fastapi.service curl -k https://localhost/api/health

Expected: PRD recovers; health 200; row counts match baseline.

8. Rollback plan (if PRD not healthy)

Use only if test-down fails or PRD remains unhealthy.

# Stop anything running sudo systemctl stop pifitness-fastapi-test.service 2>/dev/null || true pm2 delete pifitness-next-test 2>/dev/null || true # Restart PRD from original checkout cd ~/PiFitness git checkout --detach $(git rev-parse HEAD) sudo systemctl start pifitness-fastapi.service sudo systemctl start pifitness_agent.timer pifitness-hardware-health.timer
curl -k https://localhost/api/health psql -U dev -d pifitness -c "SELECT count(*) FROM activities;"

Expected: health 200 and DB accessible. If not, redeploy previous prd-YYYYMMDD tag.
