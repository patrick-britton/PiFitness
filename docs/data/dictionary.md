# Data Dictionary

Per-domain data dictionary. Each section records the grain of key tables, the canonical source for each concept, and the rules that govern the data, marked `enforced` (DB constraint) or `convention` (application agreement) with a one-line why.

## exercises

### exercises.exercise_timers
- **Grain:** one row per named exercise timer (`exercise_id` PK). A timer defines a paced protocol: name, interval, notes.
- **Canonical source:** `exercises.exercise_timers` (no upstream; user-authored).
- **Rules:**
  - `name` unique case-insensitively (`idx_exercise_timers_name`) — `enforced` — two timers with the same display name would be indistinguishable in the UI.
  - `interval_seconds` must be positive — `convention` — negative or zero intervals are meaningless for pacing; not DB-enforced.

### exercises.exercise_attempts
- **Grain:** one row per completed pacing attempt (`attempt_id` PK), tied to a timer via `exercise_id`.
- **Canonical source:** `exercises.exercise_attempts` (events generated by the app; `exercise_timers` is the parent dimension).
- **Rules:**
  - `exercise_id` references `exercise_timers.exercise_id` — `enforced` — an attempt cannot exist for a deleted timer.
  - `paced_count <= total_count` — `convention` — paced reps cannot exceed total reps; not DB-enforced.
  - `started_at < ended_at` — `convention` — an attempt must span a positive duration; not DB-enforced.
  - `interval_seconds_used` snapshots the timer's interval at attempt time — `convention` — historical accuracy; the timer's current interval may change later.
